# 使用方法

## 1. 日常问法不需要特殊格式

如果你的自定义 App 名叫“典籍参谋”或“内阁”，需要新检索时直接 @ 它，然后正常说话：

> `@内阁 我最近很纠结，要不要把刚做完的项目发给朋友看。`

> `@内阁 我怕自己太谨慎错过机会，但又怕冲动。`

> `@内阁 我总是先预演别人会不会让我失望，这件事怎么看？`

不需要额外写：

> “请从典籍里搜索至少两个案例……”

因为 MCP 的工具说明已经要求：遇到现实困惑时优先找具体原文和案例；资料支持时尽量保留不同方向，而不是只找一种古代立场。

## 2. 什么时候要再次 @ App

ChatGPT 的自定义 App 选择通常只作用于当前消息。

如果下一条消息只是继续讨论已经拿回聊天里的原文，可以直接聊；如果下一条又需要重新从典籍库取新内容，最好再次 @ App。

例如：

```text
@内阁 我纠结要不要跟朋友分享一件让我很开心的事。
```

回答后：

```text
那你刚才提到的《庄子》那个角度，我想继续聊聊。
```

这种继续讨论已有材料，不一定需要再 @。

但如果说：

```text
@内阁 再帮我查一下《世说新语》里有没有类似朋友关系的例子。
```

就需要新的检索。

## 3. 直接查书

### 看书目

> `@典籍参谋 看看我的典籍库里有哪些书。`

### 查一句话或关键词

> `@典籍参谋 在《史记》里搜“鸿门”。`

> `@典籍参谋 在《论语》里搜“君子”。`

### 全库比较

> `@典籍参谋 从现有所有典籍里找“用人无疑与防人之心”两个不同方向的例子。`

全库模式会先检查全部书，再挑案例；不会因为前几本已经找到好结果就提前收工。

## 4. 适合的现实问题

这个项目尤其适合：

- 要不要主动 / 要不要等待；
- 信任与防备；
- 朋友关系、师生关系、合作关系；
- 工作中的进退与取舍；
- 是否冒险、是否转向；
- 犹豫、错失、后悔；
- 识人、用人、听取意见；
- 原则和现实之间怎么拿捏；
- 面对流言、群体意见、讨好和承诺怎么判断。

## 5. 怎么看它的回答

理想回答应该明确区分：

1. **原文**：典籍真正写了什么；
2. **历史经过 / 结果**：事情后来怎么发展；
3. **现代解释**：为什么这个案例和你的问题有关；
4. **差异**：古代处境和你的现实有什么不能直接类比的地方；
5. **建议**：结合你的现实，而不是只靠一句古话下结论。

如果回答只给“古人曰……”却没有说明现实差异，这不是这个项目想要的效果。
